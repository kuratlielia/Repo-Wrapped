# Repo Wrapped, Product Requirements Document

Version 1.0. Owner: you. Status: build today, ship today.

## 1. One-line summary

Paste a public GitHub URL and get a swipeable, Spotify-Wrapped-style story of your year in that repo, generated by an AI agent that actually clones the repo and runs real git archaeology on it, then ends in one screenshot-ready share card.

## 2. Why this exists

Two goals, in order of priority.

First, a share loop. The product succeeds if strangers post their card to X without being asked. Personal data, a little self-deprecating, beautiful, one tap to share. That is the entire growth engine.

Second, a live proof of `@cloudflare/computer`. Every visitor gets an agent with its own computer. It clones the real repo into a durable filesystem and runs actual git commands (`git log`, `git shortlog`, `git blame`, date math) inside an isolate, not a container. This is a watchable demonstration of Cloudflare's own claim that containers should be needed for under 10 percent of an agent's work. Nearly the entire Repo Wrapped pipeline stays in isolates, which is also why it stays cheap under a viral spike.

## 3. Non-goals

Private repos are out of scope for v1. Public only. If a clone resolves as private or missing, show a friendly redirect to a public repo, not an error wall. No login, no OAuth, no token storage on launch day.

No user accounts. No persistence of personal data beyond a short-lived cache keyed by repo. No leaderboard in v1 (nice v2 idea, not today).

## 4. Target user and core loop

A developer who has a public repo they are quietly proud of. The loop:

1. Land on a clean page with a single input: paste a GitHub URL.
2. Watch a short, honest loading state while the agent works (clone, crunch, write).
3. Swipe through 8 to 12 full-screen story cards, each a punchy stat with personality.
4. Hit the final summary card, download or share it, and post it.

That is the whole product. Resist scope creep.

## 5. The cards

Eight to twelve full-screen cards. Each card is one big number or fact plus a short generated quip with personality. Order builds from warm-up stats to the personality payoff to the shareable summary.

1. Intro card. Repo name, time window (default last 12 months), a "your year in this repo" opener.
2. Total commits. The headline number, with a comparative quip.
3. The 3am club. Commits between midnight and 5am, with a nocturnal ranking.
4. Longest streak. Consecutive days with at least one commit.
5. Most-tortured file. The single most-edited file, framed as needing therapy.
6. Peak day. The most productive single day.
7. Worst commit message. Surfaces a real low-effort message from the history (`fix`, `asdf`, `please work`).
8. Busiest hour or day-of-week. When this repo actually gets worked on.
9. Top contributor. If multi-author, who carried it, by commit share.
10. Coding personality. An agent-assigned archetype derived from the patterns above (for example The Weekend Warrior, The Refactor Addict, The Friday Deploy Menace). No fixed list, the agent picks and justifies in one line.
11. Summary card. One clean, screenshot-optimized card with the top stats and the archetype. This is the artifact people post.

Rule: every card must be readable and postable as a standalone screenshot, because people will screenshot mid-story, not just the end.

## 6. Technical architecture

### 6.1 Stack

Frontend is a recent Next.js (App Router, latest stable, React Server Components where they help) deployed on Cloudflare via the Cloudflare adapter, so it runs on Workers rather than fighting them. UI is built with the shadcn component set in the brand style.

The agent work runs in a Durable Object per request using `@cloudflare/computer`. A Next.js route handler (server side) receives the repo URL, kicks off the Durable Object agent, and streams progress back to the client. Model calls go through Cloudflare AI Gateway (for caching, rate limiting, and observability) and are used only for the witty captions and the archetype. Everything else is deterministic git parsing.

Keep the split clean: Next.js owns the UI and the request entry point, the Durable Object owns the agent and its filesystem, AI Gateway owns the model calls. Do not try to run the agent inside a React component.

### 6.2 The agent pipeline

Install with `npm install @cloudflare/computer`. Attach a `Workspace` to the Durable Object storage. Per request:

1. Prepare the environment. `mkdir /workspace`, then `git clone` the target repo into `/workspace/repo`. Use `--depth` or a date window (last 12 months) to cap clone size, which you want anyway since Wrapped is a yearly story.
2. Run git archaeology in the isolate. All of the following are pure file and shell work, so they run on the cheap isolate backend, never a container:
   - `git log` with a custom format for timestamps, authors, and messages.
   - `git shortlog -sn` for contributor share.
   - Per-file edit counts via `git log --name-only` aggregation.
   - Streak, hour, and day-of-week math done in JavaScript over the parsed log.
   - Worst-message detection by scoring messages for low effort (length, known junk strings).
3. Generate captions. Batch all card quips plus the archetype into a single small model call from the computed stats, not one call per card. This is the single biggest cost lever, so keep it to one call per repo. Route it through AI Gateway.
4. Return a JSON payload of cards to the frontend, which renders the story.

### 6.2.1 Model choice and AI Gateway

Use a small, cheap model, not a frontier one. This task is easy: given a handful of precomputed numbers, write short witty lines. A tiny model clears the bar. On Workers AI, pick from the small tier (for example a GPT-OSS 20B class model, or a small Llama or Mistral variant); confirm the exact current model string against the live Workers AI models list at build time, since the catalog changes. The stats are all computed deterministically in the isolate, so the model never has to reason about correctness, only tone.

Route every call through Cloudflare AI Gateway and turn on:
- Caching, so identical stat payloads (same repo, same window) reuse the previous generation instead of paying again. This is what protects you during a viral spike.
- Rate limiting, as a spend ceiling.
- Logging, so you can watch cost and latency live on launch day.

Workers AI bills in Neurons with a daily free allocation, so a small model plus aggressive AI Gateway caching plus repo-level payload caching means most of your traffic on launch day can land inside or near the free tier. Keep outputs short (the expensive side is output tokens) by capping the response to just the quips and archetype as compact JSON.

Containers are only ever reached for a rare edge case (a repo needing a specific native tool), decided by the agent via the `exec` backend argument. In practice v1 should hit zero containers. That is the point, and the tweet.

### 6.3 Cost and viral safety

Heavy work is git and file manipulation in isolates, which spin up and tear down fast and scale horizontally, so concurrent visitors are a non-event rather than a container stampede. Workspaces can hibernate when idle. Cache the computed card payload keyed by repo plus time window, so two people wrapping the same popular open-source repo do not both recompute. The only real variable cost is the caption model calls, which you keep small.

Guardrails: cap clone depth or history window, set a hard timeout per request, and rate-limit by IP to avoid abuse during the spike.

### 6.4 Private and error handling

If clone fails as private or not found, return a typed result the frontend renders as a soft redirect card: the repo is private or does not exist, Repo Wrapped is public-only for now, here are a couple of public repos to try. Optionally a waitlist email capture for private support, which doubles as a demand signal.

## 7. Design system

These rules are strict. Follow all of them.

### 7.1 Foundations

Light mode and dark mode both required, with a proper theme toggle. Use the shadcn component set for everything (buttons, inputs, cards, dialog, toggle, skeleton, carousel, etc.) styled in the brand palette.

Color direction: minimal and clean, built on a neutral base (near-white in light mode, near-black in dark mode, with a true neutral gray scale, not a blue-tinted one) plus a single confident accent color used sparingly for the primary action, the active progress segment, and key stat highlights. One accent, not a rainbow. The accent should feel intentional and a little bold rather than corporate, since the product is funny. Everything else stays neutral so the accent actually pops.

Tone: funny and banger, but through restraint. The design is minimal and clean; the humor lives in the copy and the generated quips, not in loud visuals. Think dry, confident, a little roasting. The layout stays calm so the jokes land.

No AI slop design. That means no generic purple-to-blue gradients, no floating glassmorphism, no center-everything hero with three identical feature cards, no random drop shadows on everything. Make deliberate, specific choices.

### 7.2 Typography

Headings use Inter. Body uses Geist. No serif fonts anywhere.

Titles: line-height 110 percent, letter-spacing -3 percent.
Body: line-height 140 percent, letter-spacing -1 percent.

No monospaced text anywhere in the application, including for the repo URL, code-ish stats, or commit messages. Render everything in the normal type stack. No eyebrow labels (the small all-caps kicker above a heading) anywhere.

### 7.3 Icons

Use Lucide icons. Never place an icon on a rounded rectangle background or any filled container. Icons are always plain, sitting directly on the surface.

### 7.4 Components and layout

Never use a rounded card with a colored left-border accent. That pattern is banned.

Prefer connected grids where cells share borders and read as one unit, rather than a scatter of detached floating cards. This is encouraged, not mandatory, but it is the house look.

No emojis anywhere, in UI copy, card text, or generated captions. Instruct the caption model explicitly to never output emojis.

No em dashes anywhere, in UI copy or generated captions. Instruct the caption model to never use em dashes. Use commas, periods, or restructure the sentence instead.

### 7.5 Motion and animation

Clean, precise, purposeful animation is a core part of this product, not decoration. Use a modern animation library (Framer Motion / Motion, or the shadcn-compatible motion primitives) and keep everything consistent.

Principles:
- Fast and confident. Transitions in the 200 to 400 millisecond range, with a smooth ease (a gentle ease-out or spring), never a slow fade or a floaty drift.
- Card to card in the story uses a clean directional slide plus a slight fade, matching swipe direction. No 3D flips, no parallax layers, no bounce.
- Numbers count up on card entry (a stat like total commits animates from zero to its value once), which is the small delightful touch that makes a Wrapped feel alive. Keep it quick and only on the hero number of each card.
- Staggered reveal within a card: the number lands first, then the quip a beat later. Subtle, not theatrical.
- The loading state animates its step labels as they complete, so the wait feels like progress, not a spinner.
- Respect reduced-motion. If the user prefers reduced motion, drop the count-ups and slides to simple instant transitions.

Every animation should feel intentional and clean. If a motion does not add clarity or a small moment of delight, cut it.

## 8. Screens

1. Landing. One input, one primary button, the theme toggle, a one-line explainer. Nothing else competing for attention.
2. Loading. Honest step labels (cloning, reading history, writing your wrapped). Skeletons in brand style, no spinner soup.
3. Story. Full-screen swipeable cards, progress indicator, back and forward, a persistent share affordance.
4. Summary and share. The final card plus the share hub described in section 9.
5. Soft error. The private-or-missing redirect card described above.

## 9. Share mechanics

Sharing is the growth engine, so it gets real design attention, not a single button. Present a share hub with multiple, nicely designed options. Every generated image must be clean, on brand, and free of emojis and em dashes, in both light and dark variants.

### 9.1 Share options

- Download summary card. The single hero card as a high-resolution image, the default artifact people post.
- Carousel export. Export the best cards as a set of images sized for a platform carousel (square or portrait), so someone can post a multi-image swipeable Wrapped. This mirrors the in-app story and is highly shareable. Let the user pick which cards go in the set, with a sensible default selection.
- Share to X. Opens a composer with short, specific pre-filled text and the app URL, image attached where the platform allows. No emojis, no em dashes in the text.
- Copy link. A shareable URL to this repo's Wrapped (regenerated or served from cache), so others can view it and then wrap their own.
- Copy image to clipboard. One tap to paste straight into a post or a message.

### 9.2 In-app carousel

The story itself is a carousel. Use the shadcn carousel component for the swipeable card flow, with clean directional motion per section 7.5, a progress indicator across the top, and keyboard plus touch plus click navigation. The same card set powers both the in-app carousel and the carousel export, so they always match.

### 9.3 Image generation quality

Cards render to images server-side or via a canvas approach that exactly matches the on-screen design (same fonts, spacing, accent, and theme). Do not ship a second, uglier template just for export. What people see is what they share. Offer light and dark versions of each exported image. Every card must be visually postable on its own, since people screenshot mid-story.

## 10. Acceptance criteria for today's ship

The app is done when: a pasted public repo produces a full story within a reasonable wait; all card numbers are correct against the real git history; captions carry personality without emojis or em dashes; both light and dark modes look intentional; animations are clean, fast, and reduced-motion aware; the story carousel and the carousel export share one card set; the share hub offers download, carousel export, share to X, copy link, and copy image; every design rule in section 7 holds; private and missing repos degrade gracefully; and exported images match the on-screen design in both themes. Confirm the pipeline uses isolates only with zero container invocations on a normal public repo, caption generation is a single batched call through AI Gateway with caching on, and the model is a small cheap one, so the cost story holds under a spike.

## 11. Post-launch, not today

Private repo support behind narrow read-only OAuth with no token storage and audited agent access. A public leaderboard of wrapped repos. All-time versus yearly toggle. Org-wide Wrapped across all a team's repos. A watchable "the agent chose an isolate here, a container there" mode as a second, nerdier demo of the Cloudflare feature.
